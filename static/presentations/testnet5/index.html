BIP95 · genesis mined 2026-11-14

Testnet5 is live

A fresh test network with no difficulty exception, a minimum difficulty of about one million, and the BIP54 consensus cleanup enforced from block 1.

BIP95 by Pol Espinasa and Fabian Jahr · genesis launch coordinated by aj · bip-0095.md · launch post

Background

Third time's the charm?

Each network has its own genesis block, so coins can't be replayed between them. Addresses share the same tb1 format.

What broke Testnet4

The 20-minute rule became a CPU race

BIP95: the exception was "systematically and persistently exploited," leaving "constant re-orgs of small numbers of blocks." A bitcointalk proposal estimated about 5 in 6 Testnet4 blocks were CPU blocks.

Fix it or start over?

Patching Testnet4 was tried, then dropped

Soft-fork attempts

Core PRs #34420 (disable min-difficulty blocks after height 151,200) and #35081 (a soft fork against the exploit) were both closed in 2026.

Deployment is slow

BIP95: getting nodes to upgrade takes a long time, and the attackers farming the rule could disrupt any new deployment, BIP54 included.

A real fix is a hard fork

Anything beyond a band-aid needs hard-fork support in clients and the p2p layer. Not worth it for a test network.

  • Testnet4 kept the rule because "several reviewers insisted" CPU users should be able to mine non-standard transactions and keep the chain moving.
  • With the exception gone, the old objection to a higher difficulty floor no longer applies.

Minimum difficulty

A floor a million times higher

Why ~1M

BIP95: high enough to dampen a flood of blocks right after launch, low enough that "a handful of at-home miners or a single ASIC" can keep it usable.

What that means

At difficulty 1,048,561 a block takes ~4.5×1015 hashes: about 45 s on average for one 100 TH/s ASIC. A CPU won't get there.

BIP54 · consensus cleanup

Four new rules, live from block 1

Timewarp

First block of a period: timestamp ≥ previous block − 7200 s. Last block of a period: timestamp ≥ the period's first block (Murch–Zawy).

Sigop limit

A transaction's legacy signature operations, counted across all inputs, must not exceed 2,500. Caps worst-case block validation time.

No 64-byte txs

Transactions exactly 64 bytes without witness are invalid, closing the Merkle-tree ambiguity that can fool SPV proofs.

Unique coinbases

Coinbase nLockTime must be height − 1 and its nSequence not 0xffffffff, so duplicate coinbases are impossible without BIP30 checks.

Why a testnet for this: signet already enforces BIP54 through Bitcoin Inquisition, but signet doesn't let miners test that their own software follows the rules. Testnet5 does.

Genesis and joining

A pre-announced, publicly mined genesis

  • Anti-premine commitment: the coinbase text is the date and hash of mainnet block 975,744, the next retarget block, announced about a week ahead. The genesis timestamp is 05:03:13 UTC on 2026-11-14, 23 s after that block.
  • Built for pooled mining: an OP_RETURN output carries 8 bytes of extranonce, and BIP320 version rolling adds nonce space.
  • Fast start: 166 blocks in the first hour. Difficulty only adjusts every 2,016 blocks; the higher floor keeps early bursts in check.
  • Network: magic 0x46495645 spells FIVE; default p2p port 18353.

Node

Core support is still an open PR, #35861, so for now you build a branch.

Mine

P2Poolv2 runs its live share chain on testnet5, and aj runs a 0%-fee solo pool.

Gotcha

BIP34 height encoding: Core expects OP_1–OP_16 for heights 1–16, but much mining software pushes a byte.
